## 决议

| 项 | 决策 |
|---|---|
| 图片/视频身份 | **独立顶层实体**（`Image`、`Video` 与 `Document` 平级），各自 ID 空间（`IMG-0001`/`VID-0001`） |
| 多项目归属 | **保持单归属 + 关联项目标签**：文档有一个主 `project_id`，其他关联项目作为多值标签挂在旁（非多对多关联表） |
| 图片↔文档关联 | **关联表 + 来源字段都要**：`document_images`（document_id + image_id + 内嵌/独立标记 + 位置）；`来源` 字段记溯源 |
| 真相源物理形态 | **SQLite 数据库**（单一真相源）；图片/视频二进制放文件系统（开发期）/COS（云端），SQLite 存 URL/路径 |
| 迁移 014 粒度 | **全量迁移**：documents/versions/occurrences/projects 四类都迁（出现记录是去重基准，5316 条仅 3.1MB） |
| 迁移可回退 | **独立建库、只读导入**：不改 014 原库，指纹复算校验，对不上的列清单人工看 |

**核心判断**：在 014 三层身份模型（出现→文档→版本）上**扩展**，不推翻。新增 `Image`/`Video` 两个顶层实体，文档保持单项目归属、关联项目用标签表达。

**待 spec 细化（本轮后写）**：
- `Image`/`Video`/`Document` 的完整字段契约（继承 031 图片库的 ID/名称/sha256/字节/扩展名/原始名/来源，加 caption/尺寸/时长等）
- 关联项目标签在 SQLite 的存法（JSON 列 / 单独 tag 表）与在 WeKnora 的映射（WeKnora 标签是检索过滤维度）
- 014 指纹复算的具体校验脚本
