## Parent

#3 团队文档归档系统（全量文档库）技术方案

## What to build

扫描微信另存目录（`001-按日期缓存`），登记每条出现；三层指纹去重（byte_hash → text_fp → name_key），重复/疑似新版本给出建议，最终判定留人工。入库复制进受管目录（不动原件）。

## Acceptance criteria

- [ ] 扫描一个测试目录，新文件登记为出现（source_type、source_path、file_name、size、byte_hash、text_fp）
- [ ] 字节相同文件被标「疑似重复」（byte_hash 命中）
- [ ] 内容相同字节不同的文件被标「疑似重复」（text_fp 命中）
- [ ] 名称归一化相似但指纹不同的被标「疑似新版本」
- [ ] 永不按文件名去重（微信 `(1)` 后缀是同名避让，非第二份副本）
